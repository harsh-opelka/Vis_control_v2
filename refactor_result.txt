DELIBERATE DEVIATIONS FROM THE LITERAL SPEC TEXT (with reasons)
============================================================
1. TransferEvent carries no transfer_x field, but the orchestrator's
   OBSERVATION processing needs the current transfer-line x every frame.
   Added TransferOrchestrator.set_transfer_x(x) (thread-safe, lock-guarded)
   and RowRecord.prev_front_tangent (needed for the tripwire-crossing
   check the spec itself describes: "Store prev_front_tangent on the row
   before updating it"). Both are small, structurally necessary additions,
   not scope creep.
2. STEP 6d said "clear self._prev_tuchabzug_running" from
   _reset_tracking_session(). Implemented literally, this would have
   broken the EXISTING rising-edge detection in _on_frame (which sets
   self._prev_tuchabzug_running = True immediately before calling
   _reset_tracking_session(), so clearing it back to False there would
   make the next frame's read look like a fresh rising edge again,
   re-triggering start_cycle() every frame while TuchabzugRunning stays
   True). Instead, the new PLC_CLOTH_START/PLC_STOP_ACK submission reuses
   the `was`/`value` snapshot comparison _on_plc_tuchabzug_change already
   computes for its own rising/falling-edge detection — no new/second
   `_prev_tuchabzug_running` tracker was introduced, so there is nothing
   to "clear" and no field conflict.
3. Demo mode has no PlcClient, so _on_simulate_pulse/_demo_finish_pulse/
   _on_force_toggle_tuchabzug — the demo-mode equivalents of the PLC
   rising/falling edge — were also wired to call the same
   _submit_orchestrator_cloth_start()/_submit_orchestrator_stop_ack()
   helpers. Without this, every row driven in demo mode would sit at
   STOP_REQUESTED until stop_ack_timeout_s and ABANDON instead of ever
   transferring, since nothing would ever submit the PLC_STOP_ACK/
   PLC_CLOTH_START events demo mode needs. Not in the literal STEP 6
   snippets (which only show the PLC worker-thread callback), but
   necessary for the orchestrator to function at all in demo mode.
4. Test 2 (duplicate_crossing_blocked) and part of Test 10 call
   TransferOrchestrator._request_stop() directly (white-box) a second time
   after a normal crossing already fired once. The FSM design (a row
   leaves ACTIVE the instant it's stopped, and only ACTIVE rows are
   tripwire-evaluated) makes it structurally impossible for the *normal*
   per-frame processing path to invoke _request_stop() twice for the same
   row — which is the correct, stronger guarantee. The STOP-DUPLICATE-BLOCKED
   guard inside _request_stop() is a defense-in-depth safety net for that
   "should never happen" case, so the test exercises it directly rather
   than fabricating an artificial frame sequence that fights the FSM's own
   design to reach the same code path.
5. Row creation's `track_id` is set equal to `row_id` (RowAssociator does
   its own identity tracking via row matching; there is no separate
   sub-row association layer in this design), matching STEP 1's
   RowRecord.track_id doc ("stable association track id") without
   inventing an unused second identity space.
6. The CYCLE-END log prefix (used by shutdown()'s summary) isn't in
   STEP 4's explicit prefix list, which is read as "these must all appear
   somewhere," not "only these may ever appear" — shutdown() needed *some*
   structured summary line, and CYCLE-END (already an EventType value)
   was the natural choice.
