main_window.py changes, in detail
------------------------------------------------
  __init__:
    - self._layout_monitor: LayoutQualityMonitor | None, constructed only
      if cfg.layout_quality.enabled (None otherwise — every call site
      tolerates None).
    - self._last_layout_ratio: float | None, cache for the throttled
      display path's ratio readout.
    - _orchestrator_stop_sink (the existing single stop path) gained a
      guard: if self._layout_monitor.is_locked, log
      LAYOUT-LOCK-BLOCKED-STOP and return without stopping again.

  _run_transfer_orchestrator (production fire-decision method):
    - Immediately after `clusters = cluster_by_tangent(...)` and before
      those clusters are turned into ClusterObservations for the
      orchestrator, added a self-contained try/except block: evaluate() the
      SAME `clusters`, update() the monitor, log LAYOUT-QUALITY every fresh
      update, and on trigger call _trigger_layout_lock(). Any exception
      here is caught and logged ([LAYOUT-ERROR]) without affecting the
      orchestrator observation that follows — fail-open confirmed by
      construction (separate try block, no shared state mutated before the
      point of failure that the orchestrator path depends on).

  New methods:
    - _trigger_layout_lock(q): stops the cloth (_issue_stop_pulse), raises
      the fault via StateMachine.raise_belt_fault() + a new
      _request_plc_set_layout_error() (writes cfg.layout_quality.error_code
      to ext_error — the layout-specific counterpart to
      _request_plc_set_error()), and logs LAYOUT-LOCK-TRIGGERED at ERROR.
    - _issue_stop_pulse(): the single place a stop is actually issued
      (handle_stop_tuchabzug_trigger + push_signals_to_opcua +
      request_plc_stop_pulse) — factored out so both
      _orchestrator_stop_sink and _trigger_layout_lock call the same
      helper, per the "narrow helper both callers use" instruction. No
      TransferSnapshot was needed: neither caller actually reads snapshot
      fields inside the stop sequence itself.
    - _request_plc_set_layout_error(): layout_quality.error_code
      counterpart to the existing _request_plc_set_error().
    - _on_layout_lock_auto_cleared(): mirrors the operator-ack side effects
      (PLC ext_error clear + StateMachine.acknowledge_fault +
      _on_fault_cleared) for the auto_resume_on_good_layout=True path,
      where LayoutQualityMonitor.update() cleared itself internally.

  _on_plc_error_quit (existing operator-ack handler, STEP 0 part E): added
    one call — if the layout lock is active, clear_lock("operator_ack") —
    alongside the existing acknowledge_fault() call. No second ack listener
    was added.

  Three start_cycle() call sites (_disable_detection / STOP button, wizard
  completion, _reset_tracking_session) each gained
  `self._layout_monitor.reset()` immediately after the existing
  start_cycle() try/except — never on a raw PLC edge (confirmed:
  _on_plc_tuchabzug_change only submits orchestrator events, it never calls
  start_cycle or reset directly).

  shutdown(): added self._layout_monitor.log_session_summary() (INFO),
  wrapped in its own try/except so a summary-logging bug can't block
  the rest of shutdown.
