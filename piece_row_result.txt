F. NOT COMPLETED / DEVIATIONS, AND WHY
------------------------------------------
  1. tests/data/failing_case.jsonl does not exist, so R3
     (recorded_log_replay) SKIPS with a clear message rather than running.
     This is expected per the spec ("If the file is absent, skip... the
     operator will add it after the next run with the recorder enabled") —
     detection_recorder.enabled defaults to false in config/default.yaml, so
     no recording exists yet. Once ops enables it in the field and captures
     a real staggered-row session, drop the .jsonl at that path and R3 will
     exercise it automatically.

  2. Two spec'd log-line names could not be produced literally as written
     for a genuinely TEMPORARY (never-accepted) merge/split proposal:
     ROW-MERGE-REJECTED / ROW-SPLIT-REJECTED are only emitted by this
     implementation when the locked/near-lock guard fires (CASE D/E's
     "REJECT if locked" clause) — a proposal that simply never accumulates
     enough consecutive evidence (CASE D/E's hysteresis) logs
     ROW-MERGE-PROPOSED / ROW-SPLIT-PROPOSED (and a DEBUG evidence-reset
     line) instead, since it was never actually "rejected" in the
     locked-guard sense, just never accepted. tests/test_row_tracker.py's
     test_C_temporary_split / test_D_temporary_merge assert on the
     invariant that actually matters (no *-ACCEPTED; row_id, membership,
     and membership_version all unchanged) rather than that specific log
     prefix; test_G_locked_row_immutable covers the literal *-REJECTED path
     directly. This is documented in that test file's module docstring.

  3. RowGroup/RowTracker fixed a hysteresis gap found while writing
     test_D_temporary_merge: pending merge/split evidence counters were
     only ever incremented, never reset when a proposal stopped recurring
     (unlike pending add/remove, which are cleared explicitly). Added an
     end-of-_reconcile sweep that resets any pending merge/split entry not
     re-proposed that exact frame, matching the spec's "consecutive frames"
     requirement literally. Covered by test_D_temporary_merge (a merge
     proposal that reverts must never silently resume its evidence count
     later from a stale, non-consecutive count).

  4. STEP 5e ("call piece/row tracker shutdown/summary where
     orchestrator.shutdown() is") — PieceTracker/RowTracker have no
     shutdown/summary method in their spec'd API (only __init__/reset/
     update, plus the STEP 8 UI addition RowTracker.snapshot()). The
     concrete, load-bearing action from that instruction —
     DetectionRecorder.close() (flushing/closing the JSONL file handle) —
     is wired into MainWindow.shutdown(). No summary log was invented for
     PieceTracker/RowTracker since exposing their internal counts at
     shutdown would require new public API beyond what STEP 1/2 specified;
     flagging this rather than silently adding unspec'd surface area.

  Everything else in STEP 0-9 is implemented as specified.
